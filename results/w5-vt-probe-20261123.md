# W5 VT 131K selection probe — page-selection-gap diagnosis refuted (2026-11-23)

## Setup

- Machine: M5 Max 128GB, LSA serving path (fusion-mlx :11555, `--enable-lsa`,
  TQ k8v4), model qwen38-27b bf16, map `long-16k-1M-heavy-key-and-query-d2048`.
- Task: RULER VT, length 131072 (calibrated 131143 tokens), seed 41
  (expected `448362-336`), max-tokens 2048, greedy.
- Instrumentation: `LSA_SELECT_LOG=1 LSA_PROBE_LO=26150 LSA_PROBE_HI=26350`
  (`fusion_mlx/patches/qwen35_lsa/selection.py`; per-decode-step, per-layer
  count of selected key indices inside the probe window).
- Probe window placement: hop-1 numeric anchor (`VAR_grasveld72421 = 448362-336`)
  sits at 20% depth — token positions **26209–26230** (verified by re-deriving
  the calibrated prompt with the model tokenizer; seed 41 reproduces 131143).
  Window [26150, 26350] = 200 rows inside the anchor's 512-token page
  (page 26112–26623). Random-selection baseline: 200 × 4096/131072 ≈ 6/step.
- Live serving selection budget: `LsaSelectionConfig()` defaults — top_p 1024
  buckets, top_k 4096 keys, window 512, sink 4 (picked=4612 = 4096+512+4 ✓).

## Result (logs `~/.fusion-mlx/logs/w5-probe-{serve,run}-20261123-130429.log`)

- All 132 decode steps × 16 wrapped layers logged; `picked=4612` every step.
- **probe = 24–131 rows/step (typ. ~100), on every layer, at every step** —
  16× the random baseline. The numeric-anchor page is among the selected keys
  at every decode step, starting from step 0 (before any hop name is emitted).
- Model output: `VAR_grasveld72424 = VAR_grasveld72423`, then claims "the text
  does not provide a final numerical value" and EOS at 130 tokens (finish=stop).

## Reading

1. The 2026-11-22 diagnosis "name-similar pages crowd out the numeric anchor
   page in latent q·k selection" is **refuted at the selection level**: the
   anchor page is not crowded out — it is persistently selected. The earlier
   verdict rested on the decode-token budget probe (512→2048), which does not
   exercise the selection budget.
2. The residual VT 131K failure is **generation-side multi-hop abandonment**:
   the model halts the chain after one hop despite the anchor page being in
   its attended set every step. The dense floor fails identically — the same
   seeds (41/43) miss on the 950DT dense run and seed 42 hits on both paths
   (serving semantic 1/3 = dense 1/3 at 2048 tokens). Serving ≈ dense parity
   on VT 131K.
3. Selection behavior looks salience-driven rather than strictly query-driven
   (probe high from step 0). Consistent with NIAH 9/9 at 131K: distinctive
   pages rank high regardless of query phrasing.
4. W5 rescue target (VT 131K 0/3 → ≥2/3) is **not reachable via page
   selection** — the bottleneck is the model's chain walking at 131K, shared
   with dense. Reported unfiltered; paper claim corrected
   (experiments.tex §crosssubtask, this date).

## Side fix

`selection.py` probe block used boolean-mask indexing
(`picked[picked >= 0]`) — unsupported on current MLX
(`RuntimeError: boolean indices are not yet supported`), killing the first
decode step whenever `LSA_SELECT_LOG=1`. Fixed in fusion-mlx
`fix/lsa-select-probe-boolean-index` (347ea1fa), where-based clamp,
production path untouched (env-gated block); 14 LSA unit tests pass.
